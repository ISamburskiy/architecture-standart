### <a name="_3bfxc9a45514"></a>**Функциональные требования**
Опишите здесь верхнеуровневые Use Cases. Их нужно оформить в виде таблицы с пошаговым описанием:

|**№**|**Действующие лица или системы**|**Use Case**|**Описание**|
| :-: | :- | :- | :- |
|1|Бэк-офис кредитов + АБС<br>Сотрудник КЦ + ПО КЦ|Передача ставок сотруднику КЦ|1. Сотрудник бэк-офиса кредитов вносит в АБС информацию о ставках.<br>2. Запускается регулярная задача по передаче данных из АБС в ПО КЦ по HTTPS.<br>3. Данные записываются в БД ПО КЦ и отображаются операторам|
|2|Бэк-офис кредитов + АБС<br>Сотрудник внешнего КЦ + почтовый клиент|Передача ставок во внешний КЦ|1. Сотрудник бэк-офиса кредитов вносит в АБС информацию о ставках.<br>2. Запускается регуляная задача по формированию письма на почтовые ящики сотрудников внешнего КЦ, либо на специальный почтовый ящик внешнего КЦ. В письме передается запароленный архив, внутри которого файл с данными по ставкам.<br>3. Сотрудник внешнего КЦ получает письмо и использует информацию о ставках. 
### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**
Опишите здесь нефункциональные требования и архитектурно значимые требования.

|**№**|**Требование**|
| :-: | :- |
|1|Данные о ставках должны передаваться в КЦ по https в зашифрованном виде|
|2|Данные о ставках должны передаваться во внешний КЦ в виде файла, упакованного в запаролленый архив|
